Glossary

The eight words this course uses, exactly as .claude/skills/codebase-design/SKILL.md defines them. Print me.

TermMeaningDo not say
Module Anything with an interface and an implementation. Scale-agnostic: a function, a class, a package, a tier-spanning slice. unit, component, service
Interface Everything a caller must know to use the module correctly — types, but also invariants, ordering rules, error modes, config, performance. API, signature
Implementation What is inside the module — its body of code. —
Depth Behaviour per unit of interface. Deep = a lot of behaviour behind a small interface. Shallow = interface almost as complex as the implementation. —
Seam A place where you can change behaviour without editing at that place; where a module's interface lives. Term from Michael Feathers. boundary
Adapter A concrete thing that fills an interface at a seam. Names the role, not the substance. —
Leverage What callers get from depth: more capability per unit of interface learned. One implementation pays back across N call sites and M tests. —
Locality What maintainers get from depth: changes, bugs, knowledge, verification concentrate in one place. Fix once, fixed everywhere. —

The four principles

Deletion test Imagine deleting the module. Complexity vanishes → it was a pass-through. Complexity reappears across N callers → it was earning its keep.
Interface is the test surface Callers and tests cross the same seam. Wanting to test past the interface means the module is probably the wrong shape.
One adapter, two adapters One adapter = a hypothetical seam. Two adapters = a real one. Don't add a seam unless something actually varies across it.
Depth lives at the interface A deep module may be built of small swappable parts inside — they just are not part of the interface.
