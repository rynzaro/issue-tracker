Problem: the mock has no query semantics, so tests either echo the implementation (asserting exact findUnique arguments) or can't reach transactional paths at all — the six hierarchy transitions and both timer flows run inside $transaction, and a test must know mockTx is a separate object to touch them; that interface complexity is why they're untested.

Solution: an in-memory fake with real semantics as a second adapter at the seam services already cross — one adapter is a hypothetical seam, two make it real — so tests set up rows and assert outcomes.

  • tests assert behaviour, not call shapes
  • mockTx knowledge leaves the interface
  • with №2: transitions tested end-to-end
Speculative because the fake must track Prisma's where-clause semantics closely enough to be trusted — worth prototyping against one service before committing. Cheaper alternative if №2 lands first: test through runTaskTransition's interface and keep the mock only for leaf queries.
